# PMC requested CMS fixes — 2 November 2026

## Requirements

1. Progress number and preview use the existing `ongoing` status. The preview watches live form state; hidden progress validation permits historical values without clearing them. Public listing indicators also require ongoing status; existing detail/homepage guards remain.
2. The thirteen requested project metadata fields were already optional. Their definitions remain optional. Missing homepage construction stage no longer leaves an empty label. Project/news metadata now use explicit SEO image first, featured image second, and respect optional SEO titles. Existing absolute URL, proxy, canonical and Facebook helpers remain intact. There is no existing global image fallback to add. Nothing is written into stored SEO image fields.
3. Existing field-level Georgian fallback handles blank strings and empty rich text without writing translations, preserving zero/false. English SEO titles/descriptions and gallery captions are now editable and optional, using existing localized columns. No translation backfill occurs.
4. Shared multi-file chooser/drop control uses the authenticated existing Media REST endpoint, one independent record per successful file, bounded sequential requests from a single batch selection, deterministic order, and per-file errors. Galleries append successful uploads to native array form state. Ordinary single-image fields remain single relationships.
5. Media alt, caption and custom filesize inputs are hidden; legacy definitions/data and native file dimensions/sizes remain. Alt validation no longer blocks uploads. Blank titles derive from Unicode filenames before filename randomization; explicit locale titles and omitted existing titles on file replacement are preserved. Clearing an existing title derives its stored filename. Media has no English-specific editor inputs.
6. Shared galleries retain image relationships, optional localized captions and legacy hidden alt storage. The same gallery field covers Projects, News and Lexical gallery blocks. Existing frontend caption guards remain.
7. Public Georgian defaults, saved preferences and bilingual detail sharing behavior remain. Admin defaults explicitly use Georgian unless its language cookie selects English; browser Accept-Language no longer silently selects English in the custom interface provider. Content editing still starts in Georgian.
8. Media Library enables native bulk upload explicitly and exposes the same shared batch control used by galleries. Existing authorization, MIME/content checks, limits and S3 adapter remain.
9. No CSS, contact/Gmail implementation, domains, infrastructure, dependencies or unrelated application settings changed. The pre-existing modified `next-env.d.ts` is excluded from the commit.

## Schema and production data

Production PostgreSQL was **not modified**. No production backup was created because no production schema operation is needed or attempted. No files or existing content records were deleted. No production credentials were printed or committed.
